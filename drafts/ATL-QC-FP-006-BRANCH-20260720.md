Sunset Ep4 "The Shell" segment_0019 (TOM) failed transcript QC at similarity 98.4% because the script's "running **two** under" was transcribed by Whisper as "running **too** under" — homophones, identical audio. The spoken-number phrase parser folds the expected side's "two" → "2", so `numericTokenSequence` saw ["2","1"] vs ["1"] and tripped the `numericTokenSequenceMismatch` HARD VETO, which the ≥0.85 normalized fallback (0.984) cannot override; retries then hit REPEATED_IDENTICAL_TRUNCATION and stopped the run. Fix follows the FP-004/FP-005 pattern: one canonical fold in the shared first-stage normalizer (`normalizeSpokenNumberPhrases` in `lib/transcriptQC.ts`) — standalone "too" → "2" on both sides of both pipelines, appended at the END of the chain so it can never join an adjacent genuine number phrase ("five too many" → "5 2 many", never a fused 52). Bidirectional by construction; genuine defects still hard-fail ("two" vs "three" → "2" vs "3" in the veto stream; the truncated retry output still fails). "to" is deliberately excluded (reduced /tə/, documented Whisper boundary drops — `SAFE_TERMINAL_FUNCTION_WORDS`/`isSafeTerminalTailDrop` key on the literal token; a digit fold would turn those soft drops into numeric hard vetoes). Per the brief, other homophone classes were audited: its↔it's already converges via the possessive-strip step and their↔there already matches via the ATL-PIPE-008/A8 fuzzy rule, so both are locked by tests instead of adding redundant `HOMOPHONE_PAIRS` entries (table doc updated to say so).
